## 📌 背景与调研结论

### 1. 顶部和底部 8 个卡片“点不动”的原因
* **卡片结构**：
  * **顶部 4 个快捷卡片 (`HomeActionShelf`)**：`每日推荐`、`私人漫游`、`心动模式`、`反复聆听`
  * **底部 4 个电台卡片 (`_StationStrip`)**：`私人漫游`、`红心电台`、`心动模式`、`艺人电台`
* **根因定位**：
  在 Lazer 宿主内核（`lib/ui/home_pages.dart`）中，`onDaily` 的可点击判定条件为：
  ```dart
  onDaily: !widget.state.signedIn || (feed.quick.isEmpty && feed.daily.isEmpty)
      ? null // 为 null 时禁用，点击无任何响应！
      : () => widget.onOpenPlaylist(...)
  ```
  Lazer 的 `homeFeed` 接口期待的数据契约格式为：
  ```lua
  return {
    quick = { ... },              -- 推荐单曲列表（激活每日推荐的关键）
    daily = { ... },              -- 每日推荐专享单曲
    recommended = { ... },        -- 猜你喜欢（画廊展示的推荐歌单）
    playlists = { ... },          -- 歌单广场
    albums = { ... },             -- 为你推荐的新发行专辑
    editorialPlaylists = { ... }  -- 编辑精选歌单
  }
  ```
  而当前插件返回的是自定义的 `{ sections = ... }`，导致 `quick`、`daily` 与 `recommended` 全空，卡片全被禁用，中间的“猜你喜欢”与“编辑精选”歌单画廊也无法展示。

---

### 2. 美国 Billboard 和 B站术力口 Biliboard 匹配机制
* **上游 Lazer 对接机制**：
  网易云等上游插件内部**并未编写专门适配 Billboard 或 Biliboard 的代码**。
  Lazer 内核自带一套 **跨平台模糊搜索匹配管道（Cross-Platform Matching Pipeline）**（`lib/data/catalog.dart:758-809`）：
  1. Lazer 宿主从官方源（`billboard.com` 与 `biliboard.uk`）独立抓取各期榜单歌曲的 `(title, artist)`。
  2. 用户在 Lazer 里打开榜单时，宿主并发调用当前激活插件的 `activeGateway.search(title + " " + artist, limit: 8)`。
  3. Lazer 通过 `_chartMatchScore` 对返回候选曲目打分（标题全匹配 +0.65，翻译匹配 +0.6，歌手匹配 +0.25）。
  4. 达标后（分数 >= 0.6~0.78），自动把歌曲与榜单条目绑定，并持久化缓存 14 天！
* **YouTube 对接可行性**：
  YouTube 拥有全球最丰富、最全版权的音乐与视频音频库（特别是术力口与欧美流行），只要我们规范搜索返回字段（纯净标题、歌手、时长），匹配率会显著高于国内流媒体。

## 📝 详细实施步骤清单

### Phase 1: `homeFeed` 契约改造
- **文件**：`ytm/services/discover.lua`、`ytm/parsers/browse.lua`
- **实现**：
  1. 调用 `browse` (`browseId = "FEmusic_home"`)。
  2. 提取 `sectionListRenderer.contents`：
     - 若命中单曲货架（如 `musicResponsiveListItemRenderer` 中包含 `videoId`）：提取入 `quick` 与 `daily`。
     - 若命中歌单货架（`musicTwoRowItemRenderer` 中包含 `browseId` 以 `VL` / `RD` 开头，或包含 `playlistId`）：提取入 `recommended` 和 `editorialPlaylists`。
     - 若命中专辑货架：提取入 `albums`。
  3. 严格遵循 Lazer 的 `MusicHome` 结构返回。

### Phase 2: `playlist` 与 `playlistSongs` 契约落地
- **文件**：`ytm/services/catalog.lua`、`ytm/parsers/browse.lua`、`main.lua`、`manifest.json`
- **实现**：
  1. `manifest.json` 与 `main.lua` 的 `CAPABILITIES` 追加 `"playlists"`。
  2. 实现 `catalog_service.playlist(playlist_id)`：
     - 请求 `/youtubei/v1/browse`，携带 `browseId = playlist_id`（若未以 `VL` 开头则自动补全 `VL` 前缀）。
     - 提取歌单标题、作者、封面与曲目总数。
  3. 实现 `catalog_service.playlist_songs(playlist_id, limit, offset)`：
     - 解析出包含真实 `videoId`、`title`、`artists`、`durationMs` 的单曲列表返回给宿主。

### Phase 3: 榜单匹配与搜索调优
- **文件**：`ytm/services/catalog.lua`、`ytm/parsers/search.lua`
- **实现**：
  1. 优化 `catalog.search`：如果输入带有指定歌手或标题且首屏已获得结果，不再发起二次强制过滤补充搜索，降低并发延迟。
  2. 歌名过滤：对带有 `【MV】`、`【Official】`、`[MV]`、`【初音ミク】` 等常见视频外包装的标题做结构化提纯，同时保留规范化的 `artists` 结构，确保 Lazer 的 `_chartMatchScore` 打分高于 0.65。
