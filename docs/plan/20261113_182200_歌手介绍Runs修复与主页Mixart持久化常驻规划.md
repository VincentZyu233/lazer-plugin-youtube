## 一、背景与问题根因分析

### 1. 歌手介绍维基百科 Runs 破损与截断
* **现象**：在访问周杰伦（`@jaychou` / `UCL2MDNdwEtV6aYUgNjFQGZA`）等歌手主页时，介绍末尾显示破损的超链接与截断符号：
  `来自“Wikipedia”(https://zh.wikipedia.org/zh-cn/周杰倫)，遵... Commons Attribution CC-BY-SA 3.0(http://creativecommons.org/licenses/b...)`
* **接口抓包分析**：
  YouTube 官方服务端抓取维基百科版权声明时，URL 切分正则表达式存在 Bug，将中文后半括号 `）` 以及后面的文字（`，遵循“Creative`）误识别并吞入到了 URL 内部。
  * `runs[1].navigationEndpoint.urlEndpoint.url` 被污染为 `https://zh.wikipedia.org/zh-cn/周杰倫)，遵循“Creative`；
  * `runs[2].text` 开头丢失了 `Creative`，变成了 ` Commons Attribution CC-BY-SA 3.0”(`；
  * 官方前端因为富文本超长打上 `...`，造成了网页端与 API 外显文本和 URL 双重破损。
* **诉求**：尾部版权与链接完整保留，同时提取清洗出真实合法的维基百科 URL，恢复被吞噬的文字，呈现规范排版。

### 2. 主页 YouTube 专属合成封面（Mixart）空隐
* **现象**：Lazer 主页在连续听歌后，“编辑精选”卡片行与 YouTube 官方下发的具有标志性艺术几何封面的专属合辑（My Supermix、Discover Mix、Replay Mix 等）整体消失，主页只剩下“最近播放”与“排行榜”。
* **源码与机制溯源**：
  1. **Lazer 客户端渲染契约**（`Lazer/lib/ui/home_pages.dart:218`）：
     `if (feed.editorialPlaylists.isNotEmpty)` 才会渲染“编辑精选”货架；为空时整行被条件语句跳过。
  2. **千人千面单曲冲刷**：YouTube 推荐算法在用户活跃时，首页首屏有时会全部被单曲 / MV（`watchEndpoint`）冲刷，不包含歌单卡片（`browseEndpoint`）。
  3. **插件此前内存易失**：此前插件使用闭包局部变量 `local cached_user_mixes = {}`，未调用 Lazer 的持久化存储契约。一旦软件重启或进程重载，内存表归零，遇上单曲流首屏便无法恢复封面。

## 三、详细实施方案与伪代码

### 1. `ytm/parsers/browse.lua`（歌手 Runs 智能缝合与 URL 提纯）

新增 `browse_parser.extract_artist_description(desc_obj)`：
```lua
function browse_parser.extract_artist_description(desc_obj)
  if not desc_obj then return "" end
  local runs = desc_obj.runs
  if not runs or #runs == 0 then
    return desc_obj.text or ""
  end

  -- 若 runs 少于 3，说明没有复杂的维基百科多段结构，直接拼接
  if #runs < 3 then
    local parts = {}
    for _, r in ipairs(runs) do
      table.insert(parts, r.text or "")
    end
    return table.concat(parts, "")
  end

  -- 检测是否命中 YouTube 官方典型的 Wikipedia 撕裂模板
  local main_body = runs[1].text or ""
  local run1_url = nav.nav(runs[2], { "navigationEndpoint", "urlEndpoint", "url" }) or ""
  
  if string.find(main_body, "来自“Wikipedia”") and string.len(run1_url) > 0 then
    -- 1. 提纯维基百科纯净 URL (截去误吞的 "），遵循" 等后缀)
    local clean_wiki_url = string.match(run1_url, "^(https?://[^%)]+)") or run1_url

    -- 2. 提纯 CC 协议 URL (来自 run[4])
    local cc_url = "http://creativecommons.org/licenses/by-sa/3.0/legalcode"
    if #runs >= 4 then
      local raw_cc = nav.nav(runs[4], { "navigationEndpoint", "urlEndpoint", "url" })
      if raw_cc and string.len(raw_cc) > 0 then
        cc_url = raw_cc
      end
    end

    -- 3. 提取主体简介文本 (去除结尾残缺的 '来自“Wikipedia”(' )
    local clean_body = string.gsub(main_body, "[\r\n%s]*来自“Wikipedia”%($", "")

    -- 4. 规范重组输出
    local attribution = string.format(
      "\n\n来自“Wikipedia”（%s），遵循“Creative Commons Attribution CC-BY-SA 3.0”协议（%s）",
      clean_wiki_url,
      cc_url
    )
    return clean_body .. attribution
  end

  -- 回退通用拼接
  local parts = {}
  for _, r in ipairs(runs) do
    table.insert(parts, r.text or "")
  end
  return table.concat(parts, "")
end
```

#### B. 持久化与置顶注入逻辑
```lua
function discover_service.home_feed()
  transport.ensure_visitor_data()
  local data = transport.post_music("browse", { browseId = "FEmusic_home" }, constants.CLIENT_WEB_REMIX)
  local feed = browse_parser.parse_home_feed(data)

  -- 1. 尝试从本地持久化存储加载历史专属合辑快照
  local persisted_mixes = store.get("cached_user_mixes") or {}

  -- 2. 若本次网络请求抓取到了最新的专属 Mix，立即原子刷盘更新
  if feed.userMixes and #feed.userMixes > 0 then
    persisted_mixes = feed.userMixes
    store.set("cached_user_mixes", persisted_mixes)
  end

  -- 3. 确定最终生效的专属合辑列表 (网络最新 > 本地磁盘快照 > 官方种子兜底)
  local active_mixes = {}
  if #persisted_mixes > 0 then
    active_mixes = persisted_mixes
  else
    active_mixes = OFFICIAL_FALLBACK_MIXES
  end

  -- 4. 稳稳置顶在 feed.editorialPlaylists，100% 确保主页中段渲染
  local existing_ids = {}
  for _, p in ipairs(feed.editorialPlaylists) do
    existing_ids[p.id] = true
  end
  for i = #active_mixes, 1, -1 do
    local mix = active_mixes[i]
    if not existing_ids[mix.id] then
      existing_ids[mix.id] = true
      table.insert(feed.editorialPlaylists, 1, mix)
    end
  end

  return feed
end
```
